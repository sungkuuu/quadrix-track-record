# R47 red-team run — the qVOL realized line (keeper, public verifiers, workflows)

Red-team proof-of-concept pass over the qVOL realized line (R47), run 2026-11-04 against the public record repository at commit 60d8fe99, offline: the repository's own test doubles (a fake exchange with a tamper hook, a fake node, a throwaway key), no network, no chain write. Every block is shown next to a control that passes.

Tried: false bars (13 shapes), a mismatch between the two fetches of a day and the partial states a run can leave, eleven ways past the gap acceptance, hand-written lines (self-consistent, future-dated, duplicate, corrupted), the in-force gates, the anchor (lost receipt, lost push, dropped by a reorg, foreign sender), lateness, numeric edges, and the workflow surface.

Caught, before anything is written: a bar outside its day, a duplicated minute, non-monotonic open times, a day whose last bar is not 23:59, a close of 0 / not a number / negative, an overflow to infinity, any difference between the two fetches, and every gap-acceptance bypass (wrong day, wrong series, wrong missing list, stale entry, malformed file). Caught by the verifiers from the record alone: a future-dated, duplicate or corrupted line; a decision of another series; a decision whose anchor is not on chain (with an RPC); an anchor dropped by a reorg (with an RPC). The dry-run workflow cannot write; no workflow runs on a pull request; the node runtime cannot fall back silently.

Not caught — two standing weaknesses, both inside the stated trust boundary (the exchange's bars and the main branch of the repository): (1) bars falsified identically on both fetches — another day's prices, a one-minute shift, an open/close swap on the last bar, an absurd price — give a wrong value that is appended, anchored and shown by the vault, and both verifiers accept the record, because they recompute from the closes the line carries; (2) a self-consistent line appended by hand passes both verifiers, and the keeper's next run anchors it with its own key and builds every later window on it. Recomputation from a line's own closes cannot see bars that never came from the exchange.

Fixes recorded for the branch: the keeper recomputes a line before it anchors it and re-verifies the whole record each run; the public verifier gains a refetch-and-compare of every line's day for this series (the leverage series already has one) and checks that every anchor is sent by the key that anchored the inception decision; the watchdog runs the verifier. Lesser items: the decision id pattern, the decision's own anchor transaction, a dropped anchor, a receipt time limit, the registry's deployment transaction. Reproduce: the scripts named in the run's evidence file; each runs in under 30 seconds.

Not in these commits:

- F11 (an absurd day return could stop the record for a person) would be an operating guard outside the definition. Under the rule that no rule enters without a test, it is the owner's call. It is not implemented.

The run's attacks, run again against the keeper with these commits (the same test doubles; the stand-in node now answers transaction lookups, as a GIWA node does):
- Bars falsified identically on both fetches of a day (another day's prices, a one-minute shift, an open/close swap on the last bar, an absurd price): caught before anything is written, by the daily-candle gate, when the exchange's daily candle is the true one. Not caught when the exchange serves the same false close in both forms. That stays inside the stated trust boundary: the exchange's bars.
- A self-consistent line appended by hand: the keeper does not anchor it, because its day fetched again is not what the line records (exit 1). With the forger's own anchor: refused, because the last anchor is not the keeper's (exit 2). A future-dated, duplicate or edited line: refused by the whole-record check (exit 2).
- A ledger line whose transaction was never on chain: not in force. A decision of another series: not in force. An impostor vault with the right symbol, keeper and cap: not marked. An anchor dropped by a reorg: anchored again. A receipt that never comes: exit 1 at the time limit.
- A day accepted with a gap that Binance later fills: the next run stops (the day fetched again differs from the line) until a person confirms the change; then the series goes on, with the line as written.

The run's proof-of-concept scripts are not in this repository. To reproduce each attack and its control with the repository's own test doubles: `node --test keeper/test/vol-index.test.mjs` (T-IF17 to T-IF27).
